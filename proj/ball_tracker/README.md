# Ball-on-Plate Vision Tracker

Measures ball position and velocity on a tilting table using a single overhead camera, ArUco markers, and a Kalman filter. Outputs `(x, y, vx, vy)` in millimeters at up to 60 Hz for closed-loop control.

```
Camera (overhead)
     |
     v
+--------------+
| o ball       |   <-- Table with ArUco markers at corners
| [M0]    [M1] |
|              |
| [M2]    [M3] |
+--------------+
     ^
  Tilt motors
```

## Requirements

- Python 3.8+
- A USB or built-in camera
- 4 printed ArUco markers (generated by this repo)
- A colored ball (orange by default)

```bash
pip install opencv-python opencv-contrib-python numpy
```

## Quick Start

```bash
cd ball_tracker

# 1. Generate and print ArUco markers
python calibration/generate_markers.py
# Produces marker_0.png ... marker_3.png. Print them at ~40-50 mm and glue to table corners.

# 2. Run the tracker
python main.py
```

Press `q` in the debug window to quit.

## Calibration

### Step 1: Camera Calibration (recommended)

Removes lens distortion for better position accuracy.

1. Print a **9x6 checkerboard** with 25 mm squares (adjust `CHECKERBOARD` and `SQUARE_SIZE` in the script if yours differs).
2. Run the calibration tool:
   ```bash
   python calibration/calibrate_camera.py
   ```
3. Hold the checkerboard in front of the camera in ~20 different poses and angles. Press **`s`** each time the corners are detected (drawn on screen) to save a frame.
4. Press **`c`** to compute calibration. The script saves `calibration_data.npz`.
5. Aim for a reprojection error < 0.5 pixels.

`main.py` automatically loads `calibration/calibration_data.npz` if it exists.

### Step 2: Marker Placement

Measure the physical positions of each marker center relative to the table center (in mm) and update `MARKER_POSITIONS_TABLE` in `config.py`:

```python
MARKER_POSITIONS_TABLE = {
    0: np.array([-120.0, -120.0]),   # bottom-left
    1: np.array([ 120.0, -120.0]),   # bottom-right
    2: np.array([-120.0,  120.0]),   # top-left
    3: np.array([ 120.0,  120.0]),   # top-right
}
```

### Step 3: Ball Color Tuning

The detector uses HSV thresholds. To find the right values for your ball and lighting:

1. Open a Python shell:
   ```python
   from tracker.ball_detector import BallDetector
   bd = BallDetector()
   bd.tune_hsv(None)
   ```
2. Adjust the sliders until only the ball is visible in the mask. Press **`q`** to print the values.
3. Copy the printed `BALL_HSV_LOWER` / `BALL_HSV_UPPER` into `config.py`.

## Configuration

All tunable parameters live in **`config.py`**:

| Parameter | Default | Description |
|---|---|---|
| `CAMERA_INDEX` | `0` | Camera device index or video file path |
| `CAMERA_WIDTH/HEIGHT` | 640x480 | Capture resolution |
| `CAMERA_FPS` | 60 | Requested frame rate |
| `ARUCO_DICT_NAME` | `DICT_4X4_50` | ArUco dictionary type |
| `MARKER_POSITIONS_TABLE` | +/-120 mm | Physical marker positions on table |
| `BALL_HSV_LOWER/UPPER` | Orange | HSV range for ball color |
| `BALL_MIN/MAX_RADIUS_PX` | 5 / 80 | Valid ball size range in pixels |
| `KF_PROCESS_NOISE` | 5.0 | Kalman process noise (higher = trusts model less) |
| `KF_MEASUREMENT_NOISE` | 2.0 | Kalman measurement noise (higher = trusts camera less) |

## Hooking Up a Controller

Edit the `controller_callback` function in `main.py`. It receives a dict every frame:

```python
{
    'ball_found': bool,
    'position': (x, y),       # mm in table frame
    'velocity': (vx, vy),     # mm/s in table frame
    'markers_found': int,
    'dt': float,               # seconds since last frame
    'ball_pixel': (u, v),      # raw pixel coordinates
}
```

A minimal PD example is included. Replace it with your PID/LQR and send commands to your motor driver.

## Coordinate Frame

```
Table frame (what your controller sees):
        +Y
         ^
         |
   ------+------> +X
         |
   Origin = table center
   Units = millimeters
```

## Troubleshooting

| Problem | Fix |
|---|---|
| Markers not detected | Use matte prints, improve lighting, increase marker size |
| Ball detection flickers | Widen HSV range, add blur before detection |
| Position jumps | Ensure at least 3 markers are always visible |
| Velocity too noisy | Increase `KF_MEASUREMENT_NOISE` |
| Velocity lags | Increase `KF_PROCESS_NOISE` |
| High latency (>20 ms) | Lower resolution, skip undistortion, crop to table region |
| Ball near marker edge | Move markers further into corners, outside ball range |
